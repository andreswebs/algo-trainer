# Learnings

Problems solved and non-obvious facts found while implementing the specs in this directory. Newest entries go at the end of each section.

## Deno to Bun migration

### Phase 1: Node built-ins under Deno

- **`rm` is not a drop-in for `Deno.remove`.** Node's `rm(p)` rejects every directory unless `recursive` is set, including an empty one, while `Deno.remove(p)` deletes an empty directory. `remove()` in `src/utils/fs.ts` keeps the Deno behavior by calling `rmdir` for a directory when `recursive` is not set. The mapping table in `migrate-to-bun/reference.md` says only that `rm` fails on a non-empty directory.
- **`access` from `node:fs/promises` needs `--allow-sys` under Deno.** Deno's Node compatibility layer calls `os.uid()` inside `access`, so under the `test` task's `--allow-read --allow-write --allow-env` permissions every module that reached it failed with `NotCapable: Requires sys access to "uid"`. `pathExists()` uses `stat(p).then(() => true, () => false)` instead, which needs only read permission and matches what std `exists` does internally.
- **Raw `Deno.stdin.read` prompts read a whole buffer, not a line.** Piping `y\nextra\n` into `challenge` on an existing problem cancelled instead of overwriting, because `confirmAction` read `"y\nextra"` as one answer. The shared `readLine` helper in `src/cli/prompts.ts` reads one line per prompt, which fixes this; it is the only behavior change in phase 1. A single `y\n`, `n\n` and `/dev/null` behave as before.
- **Manual CLI checks must unset the `AT_*` variables.** A developer `.envrc` sets `AT_WORKSPACE`, which overrides the workspace even when `XDG_*` points at a temporary directory, so an ad hoc `challenge` run writes into the developer's real workspace. The `test` task already unsets them; do the same in any hand-run check.
- **A pseudo-terminal check needs no extra tooling.** `(sleep 2; printf 'y\r') | timeout 30 script -q /dev/null <command>` runs a prompt on a TTY and proves the process exits after the last read.
- **The reference spawn sketch loses signal exit codes.** `Deno.Command` reported a child killed by SIGABRT as code 134 (128 + 6); `node:child_process` reports `code` null with `signal` set, which the sketch mapped to 1. `src/core/runner.ts` maps a signal to `128 + os.constants.signals[signal]`, so a crashing C++ solution still reports 134. `Deno.Command(...).output()` also gives the child no stdin, which matches `stdio: ['ignore', 'pipe', 'pipe']`.
- **A missing executable rejects under both runtimes, with different wording.** Deno said `Failed to spawn 'cmake': entity not found`; Node says `spawn cmake ENOENT`. The runner surfaces the runtime's message, so this text changes and nothing asserts on it.
- **Deno types `import.meta.dirname` as `string | undefined`.** The phase 1 resolver form in `migrate-to-bun/reference.md`, `join(import.meta.dirname, '..', 'data')`, fails `deno check` with TS2345. `getDataRoot()` in `src/config/paths.ts` uses `fileURLToPath(new URL('../data', import.meta.url))` instead, which returns the same decoded path, works when the install path contains a space, and resolves inside a `deno compile` binary. Phase 4 replaces it with the `Bun.isStandaloneExecutable` form anyway.
- **Run a single test file through the task, never with bare `deno test`.** `deno task test <file>` forwards the file and keeps the task's isolation: `AT_*` unset and `XDG_*` in a temporary directory. A bare `deno test -A <file>` inherits the developer's `AT_WORKSPACE` and real `XDG_*` directories, so the CLI tests archive and re-scaffold problems in the real workspace and overwrite the real `config.json`. Phase 3 needs the same isolation for `bun test`, through the preload.

### Phase 2: Bun toolchain alongside Deno

- **Deno writes `package.json` dependencies into `deno.lock`.** Once a `package.json` exists, the next Deno run adds a `workspace.packageJson.dependencies` block to `deno.lock`. Resolution of `@std/*` still goes through the `deno.jsonc` import map, so the change is metadata only; commit it with the manifest or every Deno run dirties the tree.
- **Biome exits 0 on warnings.** `biome lint` and `biome ci` fail only on error-level diagnostics, and the recommended preset keeps `noUnusedVariables` and `noUnusedImports` at warning level. The `lint` script passes `--error-on-warnings` so the gate holds the zero-diagnostics policy; `biome ci` needs the same flag.
- **`biome lint --only=<rule>` force-enables the rule.** It reports a rule even where an override turns it off, so it cannot prove an override works. Run the plain lint on the file instead, and add a temporary violation of a different rule to prove the override is narrow.
- **A type-only import kept to prove an export needs a use.** `noUnusedImports` flags `import { type X as _X }`, and its fix deletes the import, which also deletes the type-check proof that `X` is exported. Reference the types from an underscore-prefixed type alias instead.
- **`pathIgnorePatterns` beats an explicit path.** `bun test ./test/x.test.ts` refuses a file listed in `bunfig.toml` `pathIgnorePatterns` and reports no matching files, so a phase 3 port removes the file from the list before `bun test <file>` can count its cases. A path without `./` is treated as a name filter, not a path.
- **Bun test discovery skips dot-directories and finds `*_test.ts`.** A test file under the gitignored `.local/` is never discovered, so a developer's TypeScript workspace there needs no ignore entry. Files named `*_test.ts`, such as `test/cli/e2e_test.ts`, are discovered even though Bun's "0 test files" message prints the glob as `_test_`.
