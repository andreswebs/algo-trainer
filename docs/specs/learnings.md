# Learnings

Problems solved and non-obvious facts found while implementing the specs in this directory. Newest entries go at the end of each section.

## Deno to Bun migration

### Phase 1: Node built-ins under Deno

- **`rm` is not a drop-in for `Deno.remove`.** Node's `rm(p)` rejects every directory unless `recursive` is set, including an empty one, while `Deno.remove(p)` deletes an empty directory. `remove()` in `src/utils/fs.ts` keeps the Deno behavior by calling `rmdir` for a directory when `recursive` is not set. The mapping table in `migrate-to-bun/reference.md` says only that `rm` fails on a non-empty directory.
- **`access` from `node:fs/promises` needs `--allow-sys` under Deno.** Deno's Node compatibility layer calls `os.uid()` inside `access`, so under the `test` task's `--allow-read --allow-write --allow-env` permissions every module that reached it failed with `NotCapable: Requires sys access to "uid"`. `pathExists()` uses `stat(p).then(() => true, () => false)` instead, which needs only read permission and matches what std `exists` does internally.
- **Raw `Deno.stdin.read` prompts read a whole buffer, not a line.** Piping `y\nextra\n` into `challenge` on an existing problem cancelled instead of overwriting, because `confirmAction` read `"y\nextra"` as one answer. The shared `readLine` helper in `src/cli/prompts.ts` reads one line per prompt, which fixes this; it is the only behavior change in phase 1. A single `y\n`, `n\n` and `/dev/null` behave as before.
- **Manual CLI checks must unset the `AT_*` variables.** A developer `.envrc` sets `AT_WORKSPACE`, which overrides the workspace even when `XDG_*` points at a temporary directory, so an ad hoc `challenge` run writes into the developer's real workspace. The `test` task already unsets them; do the same in any hand-run check.
- **A pseudo-terminal check needs no extra tooling.** `(sleep 2; printf 'y\r') | timeout 30 script -q /dev/null <command>` runs a prompt on a TTY and proves the process exits after the last read.
- **The reference spawn sketch loses signal exit codes.** `Deno.Command` reported a child killed by SIGABRT as code 134 (128 + 6); `node:child_process` reports `code` null with `signal` set, which the sketch mapped to 1. `src/core/runner.ts` maps a signal to `128 + os.constants.signals[signal]`, so a crashing C++ solution still reports 134. `Deno.Command(...).output()` also gives the child no stdin, which matches `stdio: ['ignore', 'pipe', 'pipe']`.
- **A missing executable rejects under both runtimes, with different wording.** Deno said `Failed to spawn 'cmake': entity not found`; Node says `spawn cmake ENOENT`. The runner surfaces the runtime's message, so this text changes and nothing asserts on it.
- **Deno types `import.meta.dirname` as `string | undefined`.** The phase 1 resolver form in `migrate-to-bun/reference.md`, `join(import.meta.dirname, '..', 'data')`, fails `deno check` with TS2345. `getDataRoot()` in `src/config/paths.ts` uses `fileURLToPath(new URL('../data', import.meta.url))` instead, which returns the same decoded path, works when the install path contains a space, and resolves inside a `deno compile` binary. Phase 4 replaces it with the `Bun.isStandaloneExecutable` form anyway.
- **Run a single test file through the task, never with bare `deno test`.** `deno task test <file>` forwards the file and keeps the task's isolation: `AT_*` unset and `XDG_*` in a temporary directory. A bare `deno test -A <file>` inherits the developer's `AT_WORKSPACE` and real `XDG_*` directories, so the CLI tests archive and re-scaffold problems in the real workspace and overwrite the real `config.json`. Phase 3 needs the same isolation for `bun test`, through the preload.

### Phase 2: Bun toolchain alongside Deno

- **Deno writes `package.json` dependencies into `deno.lock`.** Once a `package.json` exists, the next Deno run adds a `workspace.packageJson.dependencies` block to `deno.lock`. Resolution of `@std/*` still goes through the `deno.jsonc` import map, so the change is metadata only; commit it with the manifest or every Deno run dirties the tree.
- **Biome exits 0 on warnings.** `biome lint` and `biome ci` fail only on error-level diagnostics, and the recommended preset keeps `noUnusedVariables` and `noUnusedImports` at warning level. The `lint` script passes `--error-on-warnings` so the gate holds the zero-diagnostics policy; `biome ci` needs the same flag.
- **`biome lint --only=<rule>` force-enables the rule.** It reports a rule even where an override turns it off, so it cannot prove an override works. Run the plain lint on the file instead, and add a temporary violation of a different rule to prove the override is narrow.
- **A type-only import kept to prove an export needs a use.** `noUnusedImports` flags `import { type X as _X }`, and its fix deletes the import, which also deletes the type-check proof that `X` is exported. Reference the types from an underscore-prefixed type alias instead.
- **`pathIgnorePatterns` beats an explicit path.** `bun test ./test/x.test.ts` refuses a file listed in `bunfig.toml` `pathIgnorePatterns` and reports no matching files, so a phase 3 port removes the file from the list before `bun test <file>` can count its cases. A path without `./` is treated as a name filter, not a path.
- **Bun test discovery skips dot-directories and finds `*_test.ts`.** A test file under the gitignored `.local/` is never discovered, so a developer's TypeScript workspace there needs no ignore entry. Files named `*_test.ts`, such as `test/cli/e2e_test.ts`, are discovered even though Bun's "0 test files" message prints the glob as `_test_`.
- **`deno lint` covers the ported files too.** It lints every file under the repository, including `bun:test` files that `deno.jsonc` `test.exclude` keeps Deno from running, so until phase 4 removes Deno a ported test must also satisfy rules such as `require-await`. A rejecting fixture is `(): Promise<never> => Promise.reject(new E(...))`, not an `async` function with no `await`.
- **Read exit codes, not the last line, when chaining gates.** `deno task lint 2>&1 | tail -1` printed `Checked 100 files` while the command had failed with `Found 1 problem` on the line above. Run each gate command on its own and check `$?`, or chain them with `&&`.

### Phase 3: port the tests to bun:test

- **Bare `deno install` re-resolves `package.json` under a minimum package age.** Deno 2.9 refuses npm versions published in the last 24 hours, so `deno install` failed on an `@types/bun` release that `bun.lock` had already pinned. Bun owns `package.json`: `scripts/init.sh` runs `bun install --frozen-lockfile` and `deno install --entrypoint src/main.ts`, which caches only Deno's own graph and leaves `deno.lock` unchanged. `DENO_NO_PACKAGE_JSON=1` also avoids the resolution, but it strips the `packageJson` block from `deno.lock`.
- **Bun keeps `Object.prototype.__proto__`; Deno deletes it.** A trigger expression that looked up variables with `name in context` resolved `__proto__` to `Object.prototype` under Bun and evaluated as `true`. Bare `constructor`, `toString` and `hasOwnProperty` already evaluated as `true` under both runtimes. Look up untrusted names with `Object.hasOwn`, never with `in`.
- **Deno and Bun count BDD tests differently.** Deno reports each top-level `describe` as one test and every nested `describe` or `it` as a step; `bun test` reports each `it`. Porting the first group dropped Deno by 116 tests and 60 steps while `bun test` gained 165 cases.
- **`grep -c` over the helper names counts import lines too.** The acceptance check `grep -cE 'assertThrowsWith|assertRejectsWith'` reports one more than the site count in each file that uses a helper, because the import line matches.
- **Mechanize the port with ast-grep, and loop it.** One `ast-grep scan --update-all` pass rewrites only the outermost match, so an assertion inside a `Deno.test` callback needs a second pass; repeat until nothing applies. Decide which imports a ported file needs from call patterns (`ok($$$A)`), not from text, or a name inside a string literal leaves an unused import that both linters reject.
- **Ticket evidence covers the structure, not every step.** The port tickets shared a recipe, and reading only each ticket's evidence table missed a design step that one ticket added on top (a subprocess test for the `readLine` helper). Read every ticket's design and acceptance sections, even when its siblings are identical.
- **`deno test` fails when no test modules remain.** Once the last file moved to `bun:test`, `deno test` exited 1 on "No test modules found". `--permit-no-files` bridges the single commit before the task is deleted.
- **Test a stdin helper in a subprocess.** `readLine` binds to `process.stdin` once per process, so the test runs a fixture script with `spawnSync(process.execPath, [script], { input })`. `process.execPath` is the Bun binary under `bun test`, so no runtime name is hard-coded.

### Phase 4: cut over to Bun

- **The first Bun API in `src/` breaks every Deno gate that type-checks.** Once `getDataRoot()` used `Bun.isStandaloneExecutable` and `import.meta.dir`, `deno check` failed with TS2868 and TS2339, and `deno compile` type-checks too, so the old `validate.sh` and `fix.sh` could not pass between the data-root change and the script rewrite. The data-root commit switched `validate.sh` to `bun run typecheck` and dropped the Deno build for one commit; `deno lint` does not type-check and kept passing until `deno.jsonc` was deleted.
- **An acceptance grep can be wider than the design steps.** The data-root ticket named only `src/core/ai/parser.ts` for `Bun.YAML.parse`, but its check (`@std/yaml` only in `generator.ts`) also caught `teach validate` in `src/cli/commands/teach.ts`. Run the acceptance grep before editing, not only after.
- **`bun build --compile` leaves a copy of the runtime in the working directory.** Bun 1.4.3 on macOS writes a read-only `.<hash>-00000000.bun-build` file (about 70 MB) to the current directory on every compile and never removes it, even in an empty directory. `BUN_TMPDIR` and `TMPDIR` do not move it. The `build` script deletes it after compiling, and `.gitignore` covers builds that fail first.
- **A stale binary hides a broken smoke test.** The first `scripts/smoke.sh` run passed against a Deno-built `bin/algo-trainer` left over in the gitignored `bin/`. Delete the old binary before the first run, so the red step is real, and mutation-check the build: dropping the templates `--asset`, using `--asset ./src/data`, and a different `VERSION` each make the smoke test fail.
- **`git grep -E '\b...\b'` matches nothing on macOS.** git's extended regular expressions there do not support `\b`, so the gate grep `git grep -niE '\bdeno\b'` exited 1 on a tree with dozens of mentions and read as a pass. Use `git grep -w` for whole words, and confirm a grep that should find something does before trusting one that finds nothing.

### Phase 5: generated workspace templates

- **A syntax error hides the errors behind it.** Every generated test file failed to parse on the example prose, so nothing had ever compiled them. Once the examples became comments, the minimal Go test failed on `"testing" imported and not used`, which `gofmt -e` cannot see because it only parses. Compile and run generated code with the language's real toolchain (`go vet`, `go test`, `javac` with JUnit, `rustc --test`), not only a parser.
- **Fix multi-line placeholders where they are replaced, then sweep for the population.** `replaceAll` puts a multi-line value after the prefix of the first line only, so an indented or commented placeholder breaks from its second line on. One rule in `replacePlaceholders` (repeat the indentation or `//`, `///`, `//!` prefix) fixed the four ticketed sites and two unticketed ones in the Rust comprehensive solution. A grep for placeholders alone on a comment line showed every site the rule touches before it shipped. `#` is left out because readmes start with `# {{PROBLEM_TITLE}}`.
- **rustfmt follows `mod` declarations.** Running `rustfmt` on a generated `tests.rs` reports errors in `solution.rs`, which `mod solution;` pulls in. Check which file an error names before blaming the file you passed.
- **Empty test suites are not equally harmless.** With no test registered, `bun test`, `node --test`, `deno test`, `go test`, JUnit and a `rustc --test` binary exit 0, but `python3 -m unittest` exits 5 ("NO TESTS RAN") since Python 3.12. The minimal templates register one skipped or trivial test.

## Teaching scripts

- **A config change in one test leaks into later ones.** `configManager.updateConfig` writes the config file under the `XDG_CONFIG_HOME` that `test/setup.ts` sets once per run, so a test that sets `aiEnabled: false` made a later test that expects the default fail, but only in the full suite. Restore every changed setting in `afterEach`.
- **Read the history before deciding a feature was never built.** The built-in teaching scripts looked like an abandoned plan, but git showed 10 complete scripts deleted as collateral of a legacy-directory cleanup, and three stubs re-added only to satisfy a test. `git log --diff-filter=D -- <path>` and `git log -S <symbol>` found both in minutes.
